# 哔记 BijiBiji

独立开发的 B站课程图文笔记应用。深色场景背景与半透明玻璃工作台，左侧导入课程、右侧阅读笔记、下方保存历史。

## 下载与使用

- [下载最新源码 ZIP](./哔记-BijiBiji-源码.zip)
- [中文使用指南](./docs/使用指南.md)

下载后解压。macOS 可从项目所在目录运行 `./run.sh`，或双击上一级目录的「启动哔记.command」；首次使用请先阅读使用指南中的模型配置与隐私说明。

## 启动

当前电脑：双击上一级目录中的 `启动哔记.command`，或在本目录执行 `./run.sh`。打开 http://127.0.0.1:8766 。

新电脑需要 Python 3.11+（当前开发环境 3.10 亦通过验证）、FFmpeg 和 ffprobe。运行：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
./run.sh
```

也可以运行 `docker compose up --build -d`。Compose 默认仅绑定本机，数据保存在 `kejing-data` 卷。

## 使用

1. 打开「模型与配置」，配置笔记与画面服务。基础地址填写服务商的 API 根地址（例如 `https://供应商/v1`），不要填写完整的 `/chat/completions` 地址。
2. 笔记模型需要支持 Chat Completions；画面模型同时需要支持 `image_url` 的 base64 图片输入。兼容接口不代表每个模型都支持图片。
3. 语音转写可选择通用 OpenAI 兼容接口或豆包录音文件识别 2.0。豆包服务需在豆包语音控制台创建语音 API Key，或使用旧版控制台的 APP ID + Access Token；豆包接口地址与资源标识由程序自动设置。方舟聊天模型 API Key 与豆包语音 API Key 是不同凭证。
4. 开启字幕优先时先读取 B站字幕；字幕缺失仍需要配置语音服务。需要登录的视频可配置自己的 B站 Cookie。Cookie 不会发送给模型供应商。
5. 粘贴 B站链接或分享文字，选择笔记模板，点击生成。可先「检查链接」查看识别的 BV/av 号与分 P。
6. 生成后可以编辑 Markdown、切换模板重生成、导出 ZIP 图文资料包，或通过浏览器打印为 PDF。

**费用：**生成会调用你配置的第三方 API。原始字幕/音频、选定截图和内容材料按阶段发送到对应服务。截图数上限可调，默认 48 张。没有提供 API 配置时不会伪造处理结果；首页展示空状态。

## 支持范围

- B站标准视频链接、BV/av 号、b23.tv 短链、含标题的分享文本。
- 稍后再看、收藏/列表播放页中携带 `bvid`、`aid` 或视频路径的链接；保留 `p` 参数与旧式 `/pN` 路径。
- 没有具体视频标识的私人列表首页会提示打开具体视频；不读取整份私人收藏/稍后再看列表。
- 每次处理所选分 P，不会自动批量处理整个合集。单次上限 4 小时，下载流上限约 2 GiB。
- 当前视觉路径为定时抽帧 + 画面变化检测 + 去重 + 多模态图片分析，不是原生整段视频输入。快速动作、小字、公式仍可能识别不完整。
- 内置课程讲义、实操教程、学术报告、复习提纲，可新建/编辑/删除自定义笔记模板；自测在笔记完成后按需单独生成。
- ZIP 含笔记、按二级标题拆分的章节、原始转写、转写时间轴、画面观察和截图。章节文档使用相对路径，可离线打开。
- 原始转写不会被模型覆盖；生成笔记要求保留疑难项与来源。未实现逐词自动纠错审核或自动二次 ASR。

## 稳定性与数据

任务按单队列执行，浏览器关闭后后台继续；停止请求会在当前下载回调或阶段/模型调用边界生效。视频、转写、截图、视觉批次和中间材料保存在 `data/jobs/`。正常重试会复用缓存；「重新分析」清除分析缓存并可能重复计费。修改模型配置后如需改变分析结果，使用重新分析。

进程退出后未完成的任务标记为中断，用户可手动重试。换模板或编辑前会把旧 Markdown 保存到各任务 `versions/` 目录。当前界面没有版本切换和删除任务功能，可停机后按任务目录与数据库备份管理。

API Key 与 Cookie 存在部署机器本地 SQLite，API 不回显密钥。`data` 目录权限为 0700；这是本地访问控制，不是数据库加密。备份时请保护整个目录。默认没有多租户隔离。

## 部署到服务器

同一 Docker 镜像可部署至服务器。配置强随机 `KEJING_ACCESS_TOKEN`，通过 HTTPS 反向代理访问 8766 端口；默认 Compose 仍仅绑定服务器回环地址，反向代理连接它。浏览器会要求输入访问口令，使用 HttpOnly / SameSite cookie。当前是单用户/可信小团队部署模式，不是开放注册的多用户 SaaS。

```sh
# 在环境或 .env 中设置 KEJING_ACCESS_TOKEN 后
# docker compose up --build -d
```

不要把未设置口令的服务直接绑定到公网。长时间任务由 Python 后端和 FFmpeg 执行，需要支持常驻进程与磁盘的主机，不能仅部署为静态网站。

## 开发与测试

后端 FastAPI + SQLite，前端原生 HTML/CSS/JS，无 CDN 依赖。视频下载使用 yt-dlp，媒体处理使用 FFmpeg，帧去重使用 Pillow。未复制 BiliNote / BibiGPT 源码。

```sh
.venv/bin/python -m unittest discover -s tests -v
node --check web/app.js
```

测试覆盖链接兼容/短链域名边界、密钥隐藏、跨站写入保护、配置校验、导出相对图片路径、真实 FFmpeg 抽帧、模拟模型完整流程与缓存复用。模拟模型测试不代表真实模型的效果评测。

B站接口可能变化；下载失败时可以更新项目环境中的 yt-dlp：

```sh
.venv/bin/python -m pip install -U yt-dlp
```

## 自测学习

课程笔记完成后，点击笔记区的「生成自测」按需出题；首次生成笔记不会自动调用第二次模型。自测只依据已保存的笔记，不读取原视频字幕、截图或视频本身，最多生成 5 道知识题。题干需写明具体对象与必要背景，避免“视频中提到”“讲者说的”“这两个模型”等离开视频就无法理解的指代。每题附知识点、参考答案、解释和笔记依据摘录。

答案初始折叠。用户填写作答后可展开答案、查看讲解、标记“已掌握”或“需要复习”，也可以选择“暂时不会”。作答自动保存在该部署的数据库，刷新后从历史记录打开即可继续。没有自动评分。重新自测清空作答但不调用模型；重新生成题目会再次调用模型，旧自测记录保存在 versions 目录。

导出 ZIP 时包含单独的问题、参考答案和作答 JSON；打印笔记时输出笔记正文。

## 模型显示

右上角显示当前笔记模型，展开查看视觉、语音配置。每份新笔记底部记录实际使用的模型，使用字幕时显示 B站字幕。旧缓存未记录模型时明确标为未知，不以当前配置冒充。

## 视觉与兼容

原创书桌/树林背景、深色玻璃面板与轻微滚动视差；系统开启“减少动态效果”时关闭视差和动画。名称为哔记 BijiBiji，保留原 kejing 源码目录和 KEJING_* 环境变量以兼容既有数据与启动方式。

## 主题与文字

右上角「主题」提供雾白、米杏、浅绿、石墨四套配色，默认雾白。可调整强调色、背景颜色、面板不透明度（85%–100%）、正文和主要表单文字大小（100%–120%），也可关闭背景光影，保留随主题配色变化的弧线纹理。配色即时生效，自动保存在当前浏览器；换浏览器或设备不会同步。默认不再使用森林图片，原素材仅保留在源码中。

## 课程答疑与按需检索

生成完成后，打开笔记区的「提问」标签。答疑复用「笔记生成」模型配置，支持连续追问、补充基础知识和举例解释。选中笔记文字，再点击「解释所选内容」会把原文带入提问框；按「发送」后才调用模型。发送支持 Ctrl/Cmd + Enter，Enter 换行。

笔记右上角的「课程检索」按当前视频笔记保存设置：

- 自动（默认）：打开笔记不会建立索引。未选中文字且选择结合课程时，材料不超过 18000 字直接带入；更长材料在首次提问时建立本地关键词索引。
- 提前建立：立即用已有转写、画面分析建立索引，不重新下载或转写视频。
- 不建立：不使用索引；短材料仍可直接带入，长课程只带入笔记前 12000 字，并在回答上方说明范围。已有索引保留，但不参与此模式的答疑。

选择「通用解释」不读取课程材料；选中文字时仅带入选中文本与关键词匹配的少量课程片段，不自动建立持久索引。索引基于中文双字词和英文单词的 BM25 关键词检索，不是向量检索，可能漏掉同义表达。建索引不调用 Embedding 或聊天模型。每次答疑会发送必要材料及最多六轮有长度上限的历史对话，仍会产生模型输入/输出费用。当前没有联网搜索，也没有在答疑时重新识别截图。

对话和索引保存在本地 SQLite，与笔记按 ID 隔离。刷新后可从历史记录重新打开；换模板重新生成同一记录可复用索引，原始课程材料变化后会失效并按需重建。每个回答展示实际使用模型、材料范围和带视频时间链接的参考片段。模型被要求区分课程依据与补充解释，引用仍需核对。导出 ZIP 包含课程答疑 Markdown、JSON 和参考材料。

## 图文对照与阅读

生成笔记后默认打开「图文对照」：左侧是按章节整理的文字，右侧是该章节对应的截图。滚动任一侧跨入新章节后，另一侧会定位到同一章节；在同一章节内继续滚动时，对面不会反复跳回章节开头。阅读区的「全屏」会请求浏览器全屏并收起左侧输入栏；再次点击「退出全屏」或按 Esc 可恢复。无画面分析的纯音频笔记没有截图可供对照，可切换「笔记」或「转写文本」阅读。

「清空对话」只清空当前视频的对话，不删除笔记或索引。单视频最多保存 200 轮对话，达到上限后可先导出再清空。

### 仅使用字幕或语音（播客等）
生成按钮上方可关闭「分析视频画面」。关闭后优先读取 B 站字幕，没有可用字幕时调用已配置的语音转写服务；跳过截图提取和视觉模型调用，只根据文字材料生成笔记。此模式无需配置画面模型，但没有字幕时仍需有效的语音转写服务。当前媒体下载流程仍可能下载视频文件。

每条记录保存自己的模式，历史任务也可切换后继续处理或重新生成。切换会清理混合材料摘要缓存，保留字幕及画面原始缓存以便复用；关闭画面分析时，不把旧画面缓存送入笔记或检索。

### 章节式笔记
笔记按主题组织为内容概览、章节大纲和正文。时间链接主要放在章节标题旁；短视频少分章，较长视频按几分钟一个完整主题组织，不按字幕的秒级片段逐条写笔记。课程讲义、实操教程、学术报告、复习提纲保留各自侧重点。自测基于生成后的笔记单独按需生成。转写文本按段落合并显示，每段保留起止时间；原始转写数据仍保留。
提示词设计参考 BiliNote 的格式与风格分离、章节起点定位思路，使用本项目独立编写的规则：https://github.com/JefferyHcool/BiliNote/blob/master/backend/app/gpt/prompt_builder.py
