# 哔记 BijiBiji 使用指南

哔记把 B 站视频中的字幕或语音整理成中文课程笔记，也可以分析视频画面、对照截图、自测和追问。模型服务由使用者自行配置；API 密钥和 Cookie 保存在运行哔记的电脑或服务器上。

## 1. 安装和启动

### macOS 本机运行

1. 安装 Python 3.10 或更新版本，以及 FFmpeg（需包含 `ffmpeg` 和 `ffprobe`）。
2. 解压源码包，在终端进入解压后的项目目录。
3. 第一次运行时执行：

   ```sh
   python3 -m venv .venv
   .venv/bin/python -m pip install -r requirements.txt
   ```

4. 运行 `./run.sh`，然后在浏览器打开 <http://127.0.0.1:8766>。之后也可双击项目上一级目录中的「启动哔记.command」。

Docker 用户可在安装 Docker 后运行 `docker compose up --build -d`。本机 SQLite 数据默认保存在 Docker 卷中。

## 2. 配置模型服务

在页面右上角打开「模型与配置」。服务商应提供对应的 API 服务和模型权限；只有模型名称而没有 API 服务凭证不能调用。

### 笔记生成

- **API 基础地址**：填写服务商给出的兼容 Chat Completions 的 API 根地址，例如 `https://api.example.com/v1`。不要填控制台网页地址，也不要自行追加 `/chat/completions`。
- **模型名称**：填写服务商给出的模型 ID，而不是自己起的显示名称。
- **API Key**：填写该模型服务对应的密钥。

### 视频画面理解

要启用「分析视频画面」，还需配置支持图片输入的视觉模型。可以复用笔记服务的地址和模型，但服务商及所选模型必须实际支持图片输入，且可能需要另一个密钥。关闭画面分析后不会调用视觉模型，也不会提取截图。

### 语音转写

「语音转写」可选通用 OpenAI 兼容接口或「豆包录音识别 2.0」。选择豆包后，程序自动使用该语音服务的接口地址、模型和资源标识：

- 新版控制台：选择「豆包语音 API Key」，粘贴从豆包**语音控制台**创建的语音 API Key。
- 旧版控制台：选择 APP ID + Access Token，分别填写对应的 APP ID 和 Access Token。
- 方舟模型 API Key、控制台网页 URL 和 Doubao 模型名称都不能代替豆包语音服务凭证。需在豆包语音控制台开通录音文件识别 2.0。

API Key 输入框留空表示沿用已保存的密钥；勾选「清除已保存的密钥」才会删除。密钥保存到本地 SQLite，不会回显，也不要贴到 GitHub、截图或公开聊天中。

## 3. 导入并生成笔记

1. 将 B 站视频链接、BV 号或分享文本粘贴到「视频链接」，可先点「检查链接」确认识别到的分 P。
2. 选择课程讲义、实操教程、学术报告或复习提纲模板，可选填补充要求。
3. 视频课程保持「分析视频画面」开启即可生成文字和截图；播客或只需听内容时可关闭。
4. 点击「生成笔记」。任务会在后台继续运行；浏览器刷新或关闭后，可从历史记录继续查看。

默认优先读取 B 站字幕；获取不到字幕时才调用语音识别。若视频需要登录，在「模型与配置 → 视频处理」中填写当前有效的 B 站 Cookie。Cookie 仅用于获取视频/字幕，不会发送给模型服务。账号退出、Cookie 过期或 B 站限制变化后，可能需要重新获取 Cookie。

## 4. 阅读、图文对照与全屏

生成完成后默认打开「图文对照」：左栏是章节文字，右栏是对应截图。章节编号和标题相同，方便确认配对。

- 左右两栏都可以独立滚动。滚动跨入另一个章节时，另一栏定位到对应章节；同一章节内继续滚动不会反复跳动。
- 点击「全屏」会尝试进入浏览器全屏，并收起左侧输入栏，让图文区域占用更多空间。再次点击「退出全屏」或按 Esc 可恢复。
- 「笔记」显示完整 Markdown 笔记；「转写文本」显示原始识别文本及段落时间；「视频截图」单独浏览抽取的画面。
- 纯音频模式不会生成截图，因此「图文对照」会提示没有视频画面；笔记和转写文本仍可正常阅读。

## 5. 自测、提问和导出

- **自测**：笔记生成后，点击「生成自测」按需创建知识题。题目依据整理后的笔记生成，不会在首次生成笔记时额外调用模型。作答会自动保存；没有自动评分。
- **提问**：使用右下角「笔记提问」入口，可以结合当前笔记提问；选中笔记文字后可让模型解释所选内容。
- **导出**：点击「导出」下载包含 Markdown 和配套截图的 ZIP，或使用「打印 / 保存为 PDF」。建议定期备份整个 `data/` 目录，其中包含历史笔记、任务材料、设置及本地数据库。

## 6. 常见问题

### B 站提示 Cookie 失效或视频无法获取

确认视频在浏览器中可正常播放；需要登录的视频更新 Cookie 后重试。B 站接口、登录状态和访问限制会变化，旧任务可先点击「继续处理」，仍失败时再检查 Cookie 或更新项目环境中的 yt-dlp。

### 语音识别认证失败或返回 404

豆包转写必须使用豆包语音控制台的语音凭证，并开通「录音文件识别 2.0」。新版 API Key 与旧版 APP ID / Access Token 认证方式不要混用。选择豆包后，接口地址由程序自动配置，不要将控制台网页地址填入模型 API 基础地址。

### 图文对照没有截图

检查该任务是否开启「分析视频画面」以及是否已生成截图。纯音频笔记、未完成的任务或没有成功抽取画面的任务都没有可对照图片。

### 修改模型配置后如何重试

普通「继续处理」会复用已有字幕、语音或截图缓存；只有需要重新下载/识别/分析时才选择「重新分析视频」。重新分析可能再次调用收费服务。

### 从 GitHub 更新

下载仓库中的最新源码 ZIP，解压到新目录后按第 1 节启动。历史笔记和本地配置存在旧目录的 `data/`，更新时先备份，再将 `data/` 复制到新目录；不要把 `data/`、`.env` 或 API 密钥上传到 GitHub。

## 隐私和安全

API 密钥、Cookie、历史任务和本地数据库属于敏感信息。源码仓库不应包含这些内容。远程部署时请设置强随机 `KEJING_ACCESS_TOKEN`，通过 HTTPS 访问；不要将未设访问口令的服务直接暴露到公网。更多部署说明见项目根目录的 `README.md`。
